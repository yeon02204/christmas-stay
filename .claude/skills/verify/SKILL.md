# verify — 변경 검증

아래 순서대로 실행하고, 마지막에 결과 표를 보여줘. 실패가 있으면 원인을 고친 뒤 다시 돌려.

## 1. 자동 검사
```bash
npm run build
npm test
npm run lint
```
- 빌드/테스트 실패는 반드시 고친다. 린트 경고는 새로 생긴 것만 정리.

## 2. 규칙 점검 (`git diff` 기준으로 바뀐 부분만)
`git diff --stat` 과 `git diff` 로 변경 내용을 보고 하나씩 확인:

| 규칙 | 확인 방법 |
|---|---|
| 가짜 숙소 데이터 없음 | 새 코드/SQL 에 실제 숙소처럼 보이는 이름·가격·주소 기본값이 없는지 |
| 미입력 ≠ 0원 | 가격 관련 코드에서 `?? 0`, `|| 0`, `Number(x) || 0` 로 null 을 0 으로 바꾸는 곳이 없는지. 합계는 `src/utils/price.js` 의 `calculateTotal` 사용 |
| 미입력 ≠ 없음 | 시설 기본값이 `'unknown'` 인지, 빈 정보는 '확인 필요'/'미입력' 표시인지 |
| 날짜 분리 | 다른 날짜 구간의 rate 를 대신 쓰는 코드가 없는지 (`getRate(room, key)` 만 사용) |
| 비밀 키 | `VITE_*SECRET*`, `sb_secret_`, service_role JWT 가 없는지 |
| DB 접근 | 컴포넌트에서 `supabase.from(` / `supabase.rpc(` 직접 호출이 없는지 (`src/services/api.js` 만) |
| 마이그레이션 | 초기 파일 수정 없음, 새 테이블엔 RLS enable + 정책, `docs/DATABASE.md` 갱신 |
| 모바일 | 새 UI 가 390px 에서 넘치지 않는지 (가능하면 `browser-qa` 스킬로 확인) |

## 3. 보고 형식
```
| 항목 | 결과 |
|---|---|
| 빌드 | ✅ |
| 단위 테스트 | ✅ 13/13 |
| 린트 | ⚠️ 경고 2 (기존) |
| 규칙 점검 | ✅ / ❌ 이유 |
```
실제 Supabase 나 휴대폰에서만 확인 가능한 부분은 "미검증"으로 따로 적어. 테스트하지 않은 것을 됐다고 말하지 마.
